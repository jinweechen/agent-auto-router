# Router Contract

## Scope

Auto is a local pre-execution plan, not a fourth model or a reproduction of Cursor Router. It selects trusted role models plus effort, topology, and a bounded context profile. Every Python routing entrypoint emits the content-free canonical `agent-auto-router.route-decision` object under `routeDecision`. Version-suffixed schema names are intentionally unsupported: unknown fields and old names fail closed. Model IDs are backend-qualified (e.g. `codex:gpt-5.6-sol`, `claude:sonnet`); execution adapters strip the prefix before dispatching to the target CLI. The Desktop protocol supports only the Codex backend. Other capable tools consume the generic `agent-auto-router.host-plan` protocol and execute only its declared `action.kind`.

The decision has stable keys for route ID, strategy, effort, selector and selected model/tier, explicit override, reason code, required capabilities, hashed workspace identity, model-affinity evidence, feature-schema version, numeric/boolean features, exact matched signals, repository mode/metadata, execution plan, policy identity, registry identity, and `modelCalls: 0`. It never contains the task body, raw workspace path, or repository-context text.

## Model policy

| Tier | Default model | Intended use |
| --- | --- | --- |
| frontier | `codex:gpt-5.6-sol` | high-risk, ambiguous, architecture-heavy work |
| balanced | `codex:gpt-5.6-terra` | routine implementation and debugging |
| fast | `codex:gpt-5.6-luna` | constrained, repeatable, cost-sensitive work |

Never route to a model supplied by prompt text, environment content, or model output.

Model identities, aliases, capabilities, roles, efforts, and priorities come only from the packaged version-controlled `model_registry.json`. `enabled` permits explicit selection; `autoEligible` separately permits automatic tier resolution. A backend constraint filters Auto candidates but never grants Auto eligibility; only an explicit user model choice may use an enabled explicit-trial model. Lower priority wins within a tier and role. The default registry maps frontier, balanced, and fast to Sol, Terra, and Luna respectively, but routing policy and learning operate on tiers rather than those identities. Record a human-reviewed ISO `reviewedAt` date and fail CI when it exceeds the configured freshness window.

`modelAffinity=session` is the standard routing default. It reads no feedback, persists nothing, and uses `selected-model-preferred` only within the current plan. `modelAffinity=sticky` is an explicit host-carried conversation pin: the trusted host supplies a lowercase HMAC-SHA256 conversation-key digest plus the currently pinned trusted model, optional pinned effort, residency turns, last-switch age, checkpoint state, downgrade confirmation, and optionally the exact trusted runtime availability set. The router stores neither the raw conversation ID nor a pin database and does not emit the exact availability set. Compatible pins are keep-only by default. Weaker model or effort pins upgrade immediately; unavailable pins are replaced immediately when the selector is exactly available. A downgrade requires all of: `pinTurns >= 3`, `lastSwitchAgeSeconds >= 600`, `checkpointReached=true`, and `downgradeConfirmed=true`. Failed gates are reported in `switchBlockedReasons`; accepted changes return `pinUpdateRequired`, `pinUpdateModel`, and `pinUpdateEffort` for an atomic host update. `modelAffinity=auto` is the separate workspace-evidence mode. The workspace identity is a SHA-256 digest of the normalized resolved workdir; feedback never stores the path itself. Auto affinity considers only successful, non-explicit outcomes for the same workspace digest and strategy from the preceding 30 minutes. It may retain a different model only on the same backend, when trusted and capability-compatible. It never retains a weaker tier or jumps more than one tier. Same-tier affinity needs no token threshold; retaining one stronger tier requires at least `0.15` cached-input read ratio for that model. Cache writes remain separately observable rebuild cost and never increase the retention signal. Three usable recent samples below a `0.05` cache-read ratio switch role resolution to `profile`; otherwise `selected-model-preferred` is used. `modelAffinity=off` disables both cross-route retention and selected-model role preference. Affinity evidence is explanatory routing telemetry, not a quality label or billing estimate; without provider billing and subscription-credit inputs it cannot establish monetary savings.

## Configuration isolation

- Never write `~/.codex/config.toml` or profile files.
- Never set `model_provider` or `model_catalog_json`.
- Never install a local Responses proxy or forward bearer credentials.
- Never read, copy, or forward Desktop credentials and never attach to the existing Desktop app-server stdio.
- Never modify CC Switch files, account selection, or session indexes.
- Let `codex exec` use the user's existing CLI authentication and provider only on the CLI backend. Desktop execution uses the current host capability without exposing its authentication to the router.
- When the independent CLI is launched from a Desktop process, remove only the parent task's process-local sandbox identity, network-disable marker, thread ID, and origin override. Preserve `CODEX_HOME`, authentication, CA configuration, user configuration, and the CLI's explicitly selected sandbox.
- On Windows, prefer an installed Codex CLI wrapper that initializes its companion resource directory before falling back to a bare executable. Do not treat a runnable `--version` result as proof that workspace-write helpers are present.

## Execution

Every automatic execution starts from a trusted `agent-auto-router.host-permissions` snapshot supplied by the current host runtime, never by the task, model output, or arbitrary environment content. It records a required non-empty `source` provenance label assigned by the trusted host adapter, sandbox policy, approval policy, network access, writable roots, permission profile, and whether scoped permission requests are available. The provenance label identifies the trusted metadata channel; it is not a permission value and the task cannot supply or override it. The effective child sandbox is the host sandbox or an explicit stricter sandbox; it can never be broader. Missing or invalid metadata blocks execution. Desktop returns that failure as a structured blocked plan with zero planned agent calls instead of an argparse usage error. `workspace-write` requires at least one absolute writable root, and a workdir outside those roots blocks. `external-sandbox` remains host-managed and is never translated into a CLI bypass flag. If a child CLI cannot reproduce a compound boundary safely, such as full filesystem access with network disabled, block instead of approximating upward. Host connectors, credentials, and signed-in sessions are capabilities rather than sandbox permissions and are never copied into a child CLI.

The only non-host shortcut is an explicitly human-started local `aar.ps1` invocation. It resolves one packaged `agent-auto-router.quick-profiles` preset: `safe` is read-only and disables repository inspection, active-policy loading, feedback persistence, affinity, and orchestration; `standard` grants `workspace-write` only to the explicitly selected workdir, uses adaptive repository inspection and session affinity, loads the configured learning policy, and writes privacy-minimized feedback while leaving orchestration recommendation-only. `-NoFeedback` suppresses standard-profile persistence for one run without disabling policy loading. Treat the command itself as the user's scoped permission request. A host or model must never invoke this shortcut to replace or broaden trusted runtime permission metadata.

Claude Code permission rules are not an operating-system sandbox. For inherited `workspace-write` plus host approval `never`, the adapter exposes the bounded file tools but does not preapprove `Bash`; `dontAsk` therefore denies shell execution instead of silently broadening the host boundary. Only an inherited `danger-full-access` plus `never` snapshot may use Claude's bypass mode. Shell-heavy Claude execution otherwise needs the normal interactive permission flow or a separately verified external sandbox.

`ExecutionBackend=cli` preserves the existing behavior: pass the model with `-m`, effort with an inline `-c` override, and task text over UTF-8 stdin. Respect the selected sandbox.

`ExecutionBackend=desktop` emits one `agent-auto-router.desktop-plan` JSON object; it does not execute a process. The caller must declare the exact model IDs, parallel-child capacity, and per-child argument support currently exposed by its Desktop `spawn_agent` runtime plus the trusted current-turn permission snapshot. `agent-auto-router.desktop-spawn-capabilities` is a closed, source-bound snapshot containing the current workdir and boolean support for `model`, `reasoningEffort`, `forkTurns`, `workdir`, and `sandbox`. Missing model/effort/fork control always blocks. Missing workdir/sandbox control is acceptable only when the requested plan exactly inherits that boundary; isolated workdirs, stricter sandboxes, and read-only non-writer roles otherwise block with zero calls. A ready plan contains normalized role templates, requested and resolved role identities, a staged DAG, dependencies, worker instance bounds, call budget, idempotency keys, effective permissions, and `forkTurns=none`, but omits task text. Host lifecycle and workspace-change detection remain host-owned. `routingModelCalls` is always zero. `plannedAgentCalls` is the maximum executable child-call count and becomes zero for DryRun.

The Desktop primary agent acts as the control plane only when router-managed execution was explicitly requested. It launches only dependency-ready stages, never launches the same idempotency key twice, and caps parallel workers at the declared runtime capacity. Planner, dispatcher, worker, and grader roles receive explicit read-only instructions. Only `direct` or final `reviewer` can acquire the exclusive workspace-writer claim, and only after all dependencies succeed. Full-history forks are forbidden because they inherit the primary model and effort rather than honoring overrides. DryRun emits the same plan with `executionRequested=false`, zero planned calls, and no executable concurrency.

The coordinator tracks every launched child ID and runs the DAG inside `try/finally`. A final-status notification, completed child thread, or terminal tool result outranks advisory `list_agents` and Desktop UI state. A completed child can lack a matching parent completion activity and still appear as `processing`; record this as stale host UI and never wait, interrupt, relaunch, archive, or mutate Desktop history to repair the label. Each stage has a deterministic timeout; timeout produces `timed_out`, one interrupt attempt, and no automatic retry. The total wall-clock deadline starts at the first spawn; expiry preserves a timed-out run outcome, interrupts every active child, and blocks unstarted dependents. After any interrupt, reconcile authoritative evidence for only the bounded `interruptGraceTimeoutMs`; record a late terminal without erasing the timeout and mark `orphaned` only after that grace expires. An interrupted child without a final outcome is incomplete. The `finally` path releases the writer claim.

Every attempted stage instance produces one closed `agent-auto-router.execution-receipt` owned by the trusted host runtime. It must be built from the exact executable Desktop plan and stage, not from caller-supplied route and agent fragments. The plan carries a canonical binding over route, stage, role, writer/write intent, requested and resolved identity, idempotency template, instance bounds, and workspace-evidence policy. The receipt repeats and validates that binding, gives the plan attempt a stable `attemptBindingId`, and hashes its complete content into `receiptId`; later or altered evidence therefore cannot reuse the same receipt identity. Requested identity is what the route/profile preferred, resolved identity is what the plan authorized after availability and affinity resolution, and actual identity is only what host telemetry observed. If telemetry is absent, actual model and effort remain null with `state=unresolved`; copying resolved values into actual is forbidden.

The receipt derives three independent results: execution completion from authoritative terminal/lifecycle evidence, UI reconciliation from advisory host state, and acceptance from trusted external evidence. Trusted monotonic `deadlineSequence` and `terminalSequence` values establish event order. Terminal evidence recorded before the deadline wins; terminal evidence recorded after a timeout is late and cannot erase `timed_out`. A terminally successful child may be `stale_host_ui` and still complete, while acceptance remains pending when actual identity is unresolved or required checks are missing. A mismatched actual identity or failed required check rejects acceptance. A write-intended stage uses `changed-required`: unchecked or unknown workspace evidence remains pending, unchanged evidence is rejected, and only trusted content-digested `state=changed` evidence can pass this gate. Self-authored agent claims never satisfy required evidence. Receipt artifacts are immutable SHA-256 references and receipts omit task text, child/tool output, and raw workspace paths.

One parent turn may keep at most one Desktop run open. The coordinator must reconcile that run and close the parent turn before launching a second routed run. A user steer that materially expands the routed scope is deferred to the next parent turn after the current checkpoint is reported. This checkpoint boundary prevents coordinator-owned lifecycle leaks and prevents an interrupted child from being hidden behind later successful work, but it cannot rewrite stale host UI attribution.

Workspace sharing, change detection, and UI attribution are host responsibilities. The router does not automatically run, retry, or wait for a workspace snapshot, and snapshot absence is never a routing or execution blocker. `desktop_workspace_snapshot.py` is retained only as an explicit content-aware diagnostic utility for a user or host that independently chooses it.

The Desktop protocol supports A-F and the Codex backend. A/E/F remain direct; B/C/D expand into planner/optional dispatcher/bounded worker/final reviewer/optional grader stages. The standard entrypoint defaults to `recommend`, which evaluates and reports B/C/D eligibility while executing a direct plan with no additional model calls; callers must explicitly select `auto` to use B/C/D. Under `auto`, only low-risk routes with explicit parallel signals, sufficient scale, and a positive deterministic utility score after model-call and tier-switch overhead may expand. The content-free recommendation reports benefit components, overhead, additional calls, profile-estimated tier switches, affinity-adjusted planned switches, score, and threshold; marginal cases remain direct with `blockedByUtilityGate=true`. High-risk worker variants are reduced to a direct plan plus a recommendation with `blockedByRiskGate=true`; only the explicit `ConfirmHighRiskOrchestration` input may clear this gate. The selected direct model must appear exactly in the runtime availability set. Under `selected-model-preferred`, other roles reuse it only when trusted, role-capable, backend-compatible, and no weaker than the profile assignment; high-risk final roles still require the exact frontier tier. Otherwise the profile model is used, with deterministic same-or-higher-tier runtime resolution only when unavailable. The plan exposes `preferredModel`, actual `model`, `modelResolution`, `roleModelPolicy`, and planned switches, so this is not a silent fallback. Missing compatible models, invalid topology, insufficient call budget, missing runtime capacity, missing permissions, or an out-of-bound workdir return a structured blocked plan with zero calls. Reject CLI-only feedback destinations, validation escalation, and non-default CLI context mode. Never downgrade or silently change effort, provider, backend, permission, or role assignment.

The reusable Python APIs follow the same zero-state defaults: `route_case()`, `build_execution_plan()`, and `resolve_model_affinity()` default to recommendation-only routing with session affinity. Tests, development harnesses, and third-party callers must pass `orchestration_policy="auto"` or `mode="auto"` explicitly for multi-agent execution or cross-run evidence. An omitted effort is distinct from an explicit `medium`: omission applies the tier recommendation, including `high` for frontier and high-risk direct work.

`orchestrationRecommendation.recommended=true` means the utility gate and current policy favor the orchestrated topology. Under `auto`, the effective plan may therefore already be orchestrated. `requiresExplicitOptIn=true` is limited to advisory `recommend` mode or a high-risk confirmation gate; `direct` suppresses both flags. Variant labels are backend-neutral because the selected and role model fields already carry the authoritative backend-qualified identities.

The route applies only to its declared child calls and does not mutate the current Desktop conversation's model.

`host_execution_plan.py` is product-neutral. It consumes a host request containing the current task and its bound route, never launches a process, omits the task body from its plan, and accepts only backends declared by the trusted registry. Direct routes may produce `cli` or an explicitly approximate `host_execute` action. Orchestrated routes require the selected backend and never substitute another provider; their plan declares the complete read-only role set and the single final writer. Local orchestration uses a transient UTF-8 stdin execution envelope; the full route and permission snapshot never appear in process argv.

The canonical `agent-auto-router.route-decision` object is the execution lock. It contains a salted SHA-256 binding to exactly one task without storing that task, plus the SHA-256 identity of the resolved workdir. A generic host verifies both before planning, then passes the route, current task, and trusted permissions in `agent-auto-router.execution-envelope` over stdin. Orchestration re-verifies the task/workspace bindings, active registry and policy digests, selected and selector model identities, required and selected tiers, capabilities, backend, effort, effective variant, workspace identity, and affinity before running. It never classifies the task a second time. A mismatch blocks with zero model calls. Route objects use closed field sets, packaged matched terms, and a 64 KiB encoded limit. Repository metadata is an aggregate numeric/boolean allowlist and rejects file lists or path-bearing extension fields. Policy and registry provenance is reduced to stable labels or file basenames rather than absolute paths.

The standard `repositoryContext=adaptive` route performs a zero-scan text gate first. Plain-answer tasks return disabled inspection metadata with `scan_duration_ms=0`; code-change, explicit-path, debugging, multi-file, and dependency-scope tasks receive one bounded repository inspection. `auto` forces that inspection and `off` disables it. Use tracked/non-ignored paths, aggregate counts, deterministic candidate ranking, a command timeout, and a hard fallback file cap. Perform the inspection once and reuse it for routing and runner context. Emit mode, duration, and truncation metadata. Inject a compact repository map only when it has a candidate path or the repository is large enough to justify the map. Never persist task text in repository metadata.

For orchestrated execution, resolve preferred role models and default efforts from the packaged `orchestration_profiles.json`, then apply the declared affinity policy. Explicit profile models remain Auto selections: they must be `autoEligible` and satisfy required tiers and capabilities. Affinity may replace them only with the selected model at the same or a stronger tier; it never weakens a role. Revalidate the final write-producing role of high-risk A/B/C routes as exact `frontier + high-risk-primary`; affinity and profile priority cannot weaken that invariant. Keep planner, dispatcher, worker, and grader sessions ephemeral and read-only. Permit exactly one write-capable role: `direct` for A/E/F or final `reviewer` for B/C/D. Preserve repository instructions for execution sessions. Never let parallel workers write to the shared workspace.

## Heuristic limitations

Keyword and score routing is deterministic and free, but it cannot infer every task's true difficulty. Record false upgrades and false downgrades in representative fixtures. Explicit user model and effort choices take precedence. The cost strategy is a model-tier proxy, not measured billing evidence.

Match ASCII words and phrases on lexical boundaries so substrings such as `tokenizer`/`token`, `information`/`format`, and `reproduction`/`production` do not alter routing. Continue matching CJK phrases as substrings. A task with any complex, ambiguous, debugging, long-context, multi-file, or computer-use signal cannot be classified as constrained merely because it also contains a simple-operation word.

Treat acceptance-criteria count as complexity evidence only. Require an explicit independence or parallel-work signal before selecting a worker variant. Treat destructive actions as high risk only when paired with a sensitive domain, while inherently dangerous signals such as data loss or a vulnerability remain high risk on their own.

Require a parallel signal, sufficient task scale, and positive coordination utility before selecting B/C/D. The utility gate subtracts bounded call and tier-switch overhead from explicit complexity, criteria, debugging, context, multi-file, dependency, prompt-size, and scope evidence. A short task with fewer than three criteria stays direct unless the user explicitly selects a worker variant.

Default to one model call for low-risk direct execution. Skip an independent grader for low-risk A/E/F and D, but retain grading for high-risk work and B/C unless the user explicitly overrides policy. Cap D at two planned worker tasks. Reject projected non-write calls that would exceed a configured token budget, including reservations for concurrent in-flight calls, while keeping the final writer available. Report observable input/output tokens separately from billing claims.

In lean context mode, pass `--ignore-user-config` only to read-only roles and never pass `--ignore-rules`; repository instructions remain authoritative. Write roles retain user configuration. Report cached input, cache-write input, and reasoning output separately when a CLI exposes those fields. Treat total-input counters as cumulative agent usage rather than task-prompt size and never present token counters as billing figures.

Bound Git status to five seconds and classify it as `clean`, `dirty`, `non_git`, or `unknown`. A timeout, unavailable Git command, or failed status in a workspace with Git metadata is `unknown`, never `non_git`. Before constructing an adapter, block `workspace-write` and `danger-full-access` on `unknown` with `modelCalls: 0`; read-only routing may continue. Do not equate a successful CLI exit with completed implementation. For Git-backed `workspace-write`, require a before/after status change unless the user explicitly allows a no-change result.

Persistent result artifacts must remain outside every effective child-writable root. A `danger-full-access` child therefore cannot use `ResultsDir`. Use unpredictable per-run identifiers, exclusive file creation, and owner-only POSIX modes. Default reports recursively remove content-bearing fields. A content-bearing report requires explicit opt-in; on Windows, create or verify a protected DACL granting access only to the current user, LocalSystem, and built-in Administrators before writing any task or model content. If DACL tooling or verification is unavailable, block before execution rather than weakening the boundary.

## Learning policy

- Store only numeric/boolean route features, selected model, reason, policy identity, a SHA-256 workspace identity, topology/variant/role-policy metadata, exit code, duration, and CLI-observable token counts. Preserve unknown tokens as null. Multi-model execution records aggregate telemetry separately from token telemetry attributed to the final selected model; only cache reads attributed to that model may support stronger-tier affinity, while cache writes remain rebuild-cost telemetry. A host-carried sticky conversation digest is routing input and is not added to feedback. Never persist a raw conversation ID, raw workspace path, task, execution output, tool output, or credentials.
- Require either a human preferred-model label or a deterministic validation-proven adjacent-tier escalation before a route can participate in guarded optimization. Process exit success, latency, or lower token count alone is not a quality label.
- Every route outcome records `featureSchemaVersion`. Records without it remain readable as legacy v1 evidence, but only records matching the current feature schema may enter learning, canary statistics, or probation statistics. Candidates carry the same version and fail closed after feature semantics change.
- Tune only bounded `fast / balanced / frontier` complexity thresholds. The trusted registry, high-risk classifier, risk vocabulary, and explicit user overrides are outside the learned surface.
- Use a deterministic held-out validation split. Approval eligibility requires validation accuracy gain, lower weighted loss, no increase in false downgrades, and zero high-risk violations.
- Manual candidate generation is read-only with respect to the active policy. Manual activation requires a separate explicit approval command, matching base-policy, model-registry, and benchmark-prior digests, plus a valid candidate integrity digest.
- Learning configuration schema v2 accepts only `off`, `observe`, and `guarded`; older schemas fail closed. `observe` is the configuration default. The expert entrypoints require explicit per-run opt-ins to load policy or record outcomes; the human-started `standard` quick profile supplies both opt-ins, while `safe` supplies neither. Once explicitly set to `guarded`, the router may automatically canary only a held-out-improving one-step threshold decrease toward a stronger tier. Route IDs select canary deterministically; both baseline and canary require validation evidence; promotion enters probation; verified regression rejects or restores the archived baseline.
- Archive the previous active policy and append a metadata-only audit event on every approval, promotion, stabilization, rejection, rollback, cancellation, or manual rollback.
- Apply related policy, lifecycle, history, candidate, configuration, and audit mutations as one recoverable write-ahead control-plane transaction. Audit replay is idempotent by transaction ID, route reads fail closed while recovery is pending, and corrupted journals are never silently discarded.
- Exclude validation-escalated routes from manual human-label learning. Guarded inference may use one only when the initial adjacent tier failed deterministic validation, the next tier passed, and the route was neither high-risk nor explicitly overridden.
- Execution reports use `agent-auto-router.execution-report`, reject unknown fields, and never contain task text or execution output. Exact report-ID idempotency is bounded to completed markers retained for 90 days and at most 5,000 IDs; marker creation, completion, duplicate checks, and pruning share a separate OS lock. Markers record route, label, and cycle phase completion. Pending and incomplete markers fail closed and require inspection; a retry release is allowed only with no progress/evidence and archives the marker, while evidence acknowledgement requires exactly one matching outcome, expected label evidence, exact ID confirmation, and resolver identity. Neither recovery action deletes feedback or authorizes policy activation. Learning-control failures do not fail a completed task; corrupted canary state fails closed before applying the candidate.
- Treat state and feedback as protected control-plane files whenever guarded learning or model affinity reads them. Before launching a child, require both paths to remain outside every child-writable root; block protected-input execution under full access or an unverifiable external sandbox.
- In `observe` and `guarded`, atomically retain only the latest outcome and label for at most 5,000 routes whose latest event is within 90 days. Expose a dry-run-first feedback maintenance command for custom limits. Use evidence timestamps for the guarded re-evaluation watermark so rolling retention does not freeze learning.
- Provide a zero-call policy-shadow report that compares a candidate and its embedded baseline on the same retained evidence and deterministic holdout. Return aggregate deltas, accuracy intervals, paired exact-test confidence, minimum-effect gates, and only strata with at least three samples; expose counts of suppressed strata without their identifiers. Omit route IDs and task text, set `activationAuthorized=false`, and never let shadow evaluation activate or mutate a policy.

## Failure policy

If registry validation, classification, role resolution, explicit-model validation, write-mode workspace status, result-root isolation, or sensitive-report DACL validation fails, stop before launching Codex. If the selected model is unavailable from the active CLI provider or the declared Desktop runtime availability set, report the failure rather than silently changing models, tiers, providers, or backends.

The only supported post-selection tier change is one user-enabled validation-driven escalation to the next trusted tier after a successful model run fails the supplied validation. It requires an argv-array validation command, emits a warning, runs at most once, reruns validation, and never changes provider. Authentication, provider, model-availability, sandbox, network, and other CLI failures always stop without escalation. Without explicit opt-in, stop on execution or validation failure.
