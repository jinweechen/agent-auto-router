# Security and audit remediation — 2026-08-11

This record separates findings verified in the current repository from claims that describe another revision or a different integration. It is not a penetration-test certificate. Runtime availability, provider billing, and operating-system access control still require deployment-specific verification.

## Decision rules

- `Fixed` means the current change set contains an implementation and a regression test.
- `Existing control` means the current repository already contains the stated boundary and no code change was required.
- `Residual limitation` means the behavior is inherent or intentionally retained and must remain visible to users.
- `Not reproduced` means repository-wide inspection found no matching implementation in this revision.

## Release gates

This change set is acceptable only if all of the following hold:

1. Auto never selects an `autoEligible: false` model merely because a backend was specified.
2. Validation escalation never crosses the declared backend and blocks when that backend has no eligible next tier.
3. Default reports contain no task/model-output/absolute-path content, use exclusive creation, and cannot overwrite an existing report; destinations remain outside every child-writable root, and sensitive Windows reports pass real DACL verification.
4. Feedback rejects content fields and records cache-write telemetry only as non-negative numeric metadata.
5. Repository inspection is bounded, reusable, observable, and disableable.
6. Registry validation fails closed on a missing, future, or stale review date when `--fail-on-stale` is used.
7. Unit tests, offline evaluation, plugin validation, Skill validation, and the official Skill validator pass without a model call.
8. No installation, real model invocation, commit, or push is performed as part of this remediation verification.
9. Write-capable orchestration blocks on an unknown Git status before adapter construction.
10. Canonical route decisions have identical keys across Python entrypoints and contain no task body.
11. The `safe` quick profile remains read-only with feedback disabled, and the `standard` profile can write only the explicit workdir; neither profile accepts user-defined permission fields.
12. Learning config accepts only schema v2 `off / observe / guarded`; `off` creates no feedback artifact, `observe` never changes policy, and `guarded` retains canary/probation/rollback gates.
13. Default automatic orchestration never expands a high-risk route; it emits a confirmation-required recommendation instead.
14. Marginal worker plans fail the utility gate, while useful parallel plans expose content-free score components and remain reachable.
15. Feedback retention previews before mutation, preserves route/label pairs, and reports `storesTaskText=false` and `modelCalls=0`.
16. Execution-report retention never silently removes pending, incomplete, or corrupt markers, and duplicate checks share the retention lock.
17. Report recovery requires inspection and exact confirmation, archives empty markers before retry, preserves existing feedback, and never authorizes policy mutation.
18. Policy shadowing is read-only, suppresses undersized strata, separates effect size from paired confidence, omits route IDs, returns `activationAuthorized=false`, and leaves candidate/lifecycle files byte-identical.
19. Model affinity never retains a weaker, cross-backend, capability-incompatible, or more-than-one-tier-stronger model; stronger-tier retention requires cache evidence and expires after 30 minutes.
20. Role affinity reduces planned tier switches only when the selected model meets every role floor; high-risk final roles retain their exact frontier requirement.
21. Feedback stores only a SHA-256 workspace identity, never the raw path, and affinity-enabled execution protects state and feedback from child writes even in `observe` mode.
